Project Overview

This project demonstrates collaborative autonomous mobile robotics using ROS 2, focusing on distributed multi-robot coordination for efficient environmental exploration. Two independent robots (TurtleBot3 platform) operate under separate ROS 2 namespaces with their own SLAM stacks, while a centralized coordinator optimizes frontier exploration and maintains a shared world model. The architecture emphasizes modular design, clear separation of concerns, and scalability to additional robots.

Multi-Robot Distributed Architecture

  • Namespace Isolation: Each robot operates under independent ROS 2 namespaces (/robot1, /robot2) with isolated topics, services, and TF trees. This design pattern ensures no topic name conflicts and allows seamless addition of more robots to the system. TF frames follow the pattern robot1/base_link, robot2/base_link to maintain clarity across the distributed system.
  • Independent Navigation Stacks: Each robot runs its own Nav2 stack with separate planner and controller servers. Robots navigate autonomously using local costmaps (updated from LiDAR) and global costmaps (updated from SLAM maps). This per-robot architecture allows independent goal processing while maintaining shared coordination through the central coordinator.
  • Distributed SLAM per Robot: Implemented Independent SLAM (slam_toolbox) for each robot to build local occupancy grid maps. Each robot maintains its own map frame and transforms: robot1/map → robot1/odom → robot1/base_link. The local maps serve as the basis for frontier detection and form raw material for the shared world model.
  • Frontier Detection & Extraction: Developed frontier detection algorithm that scans each robot's local occupancy grid to identify boundaries between free and unexplored space. Frontiers are clustered based on spatial proximity, filtered by minimum size to avoid noise, and ranked by information gain. Frontier centroids provide exploration targets for the coordinator's allocation algorithm.
  • Centralized Coordination & Goal Allocation: Implemented centralized coordinator node that receives frontier lists from both robots, tracks robot states, and allocates unique exploration goals to avoid redundant frontier assignments. Uses distance-based cost calculation with conflict penalty to maximize coverage efficiency: robots are directed to different frontiers rather than both converging on the same target.
  • Shared World Model & Map Fusion: Developed shared world model node that aggregates local SLAM maps from both robots into a unified global occupancy grid. Map fusion uses conservative strategy: if either robot detects an obstacle at a location, it is marked as occupied in the shared map. This design enables one robot to benefit from environmental information detected by the other robot, demonstrating the value of cooperative exploration.
  • TF Frame Hierarchy & Transforms: Carefully managed coordinate frames to avoid collisions: each robot has prefixed frames, but the shared TF tree bridges them. The map fusion process requires explicit transforms between robot-local frames and a global reference frame. This deep understanding of TF2 coordinate systems is essential for multi-robot robotics.
  • ROS 2 Distributed Communication: Utilized ROS 2 publish-subscribe model for asynchronous inter-node communication. Robot-specific topics (/robot1/scan, /robot1/odom) stay namespaced. Shared topics (/shared/global_map, /shared/frontiers) carry aggregated information. QoS settings adapted per topic type: sensor streams use best-effort, map data uses reliable + transient local.
  • Gazebo Simulation & Headless Operation: Implemented complete simulation environment using Gazebo headless mode (compatible with WSL2 on Windows). Spawns two robots with separate models, manages physics simulation at 1000 Hz, broadcasts simulated time via /clock topic for synchronized execution of all ROS 2 nodes.
  • Modular Development Phases: Designed system with clear development milestones (10 phases) ensuring every checkpoint produces working code. Phase 0-1: Basic multi-robot simulation. Phase 2: Independent Nav2 navigation. Phase 3: SLAM for each robot. Phase 4: Frontier detection. Phase 5: Centralized coordination. Phase 6: Shared world model. Phase 7: Optional semantic perception. This approach emphasizes understanding over complexity.
  • Engineering Integration Outcomes: Provided comprehensive experience in ROS 2 middleware, multi-robot systems, namespace management, TF coordinate frames, SLAM, frontier-based exploration, centralized coordination algorithms, occupancy grid fusion, Gazebo simulation, Nav2 navigation stack, and distributed system design patterns. Demonstrated practical ability to design, implement, and test systems that scale from single-robot to multi-robot architectures.

Development Phases & Incremental Architecture

0-1

Environment Setup & Dual-Robot Simulation ✅

Verified Ubuntu/ROS 2 Humble environment. Configured Gazebo headless operation (WSL2 compatible). Implemented multi-robot spawn system with TurtleBot3 models under separate namespaces. Established TF frame hierarchy for both robots avoiding name collisions.

2

Navigation2 Per-Robot Implementation ✅

Deployed independent Nav2 stacks for both robots. Configured planner servers (NavfnPlanner), controller servers (RegulatedPurePursuitController), and behavior tree navigators. Created modular parameter files for shared base config + robot-specific overrides. Tested autonomous goal-based navigation for each robot.

3

Distributed SLAM Implementation ⬜ Planned

Integrate slam_toolbox for each robot independently. Each robot builds local occupancy grid map. Establish map→odom→base_link TF chain per robot. Validate SLAM accuracy and odometry drift handling.

4

Frontier Detection & Extraction ⬜ Planned

Implement frontier detection algorithm: scan occupancy grids for free-unknown boundaries, cluster connected frontiers, filter by size, calculate information gain. Publish frontier centroids as visualization markers and structured data.

5

Centralized Coordinator & Goal Allocation ⬜ Planned

Develop coordinator node tracking robot states and frontiers. Implement distance-based goal allocation algorithm to assign unique frontiers to robots. Send navigation goals via Nav2 action interface. Optimize for exploration efficiency and frontier conflict avoidance.

6

Shared World Model & Map Fusion ⬜ Planned

Create shared world model node. Implement occupancy grid fusion: merge robot-local maps into global frame. Apply transforms between robot maps and shared coordinates. Enable one robot to benefit from another's perception, demonstrating collaborative advantage.

7

Semantic Perception (Optional) ⬜ Planned

Optional extension: Implement semantic object detection on Robot 2's camera feed. Store detections in shared world model with 3D pose. Demonstrate one robot navigating to semantically detected objects even if that robot never detected them directly.

8-10

Testing, Metrics & Evaluation ⬜ Planned

Conduct comprehensive experiments: measure coverage efficiency (area explored per time), frontier allocation success rate, map accuracy, path planning performance. Generate performance reports and comparison metrics (coordinated vs. independent exploration). Document system architecture and lessons learned.
