Project Overview

This project focused on the development and evaluation of a ROS 2-based autonomous navigation pipeline for mobile robotic platforms, integrating environmental perception, mapping, localization, global path planning, local trajectory generation, and obstacle avoidance. Conducted in Bourges, France, the objective was to create a modular navigation architecture capable of transforming raw sensor information and a desired target pose into safe motion commands while continuously estimating the robot's state and adapting its trajectory to the surrounding environment. The project emphasized real-world validation in dynamic indoor and industrial settings.

ROS 2 System Architecture & Modular Design

  • Distributed ROS 2 System: Software structured as a distributed robotic system where sensing, localization, planning, visualization, and control components communicate through standardized topics, messages, and coordinate transformations. Emphasized interaction between global map reference frame, local odometry frame, robot base_link, and sensor reference frames. Modular structure allowed navigation components to be evaluated independently while maintaining clear interfaces between perception, planning, and motion-control subsystems.
  • Multi-Sensor Perception & Data Fusion: Integrated LiDAR, camera, IMU, and odometry information providing complementary perception of robot and environment. LiDAR measurements used for geometric obstacle perception and mapping, while inertial and odometric measurements supported robot-motion estimation. Camera provided additional perception modality for object and environment interpretation. Heterogeneous sensor integration provided practical experience with sensor interfaces, coordinate frames, timing, data quality, and perception challenges.
  • SLAM & Localization: Implemented Simultaneous Localization and Mapping (SLAM) to construct environmental representation while simultaneously estimating robot pose. Generated map formed global reference used by navigation pipeline. For navigation inside existing maps, localization methods continuously estimated robot position and orientation from sensor observations and motion information. Required understanding interaction between mapping accuracy, odometry drift, sensor uncertainty, coordinate transformations, and navigation performance.
  • Global Motion Planning Strategies: Explored graph- and sampling-based planning approaches including Dijkstra and RRT*. Dijkstra provided deterministic shortest-path search over structured environmental representations. RRT* offered sampling-based alternative capable of exploring configuration space and progressively improving candidate trajectories. Implementing and comparing different strategies provided insight into trade-offs between optimality, computation time, environmental complexity, and path geometry.
  • Local Planning & Obstacle Avoidance: Implemented Dynamic Window Approach (DWA)-based local navigation strategy continuously evaluating feasible robot motions while respecting local obstacles and kinematic limitations. Local planner generated short-horizon velocity commands according to robot's immediate surroundings and updated trajectory when environmental conditions changed. Separation between global path generation and local reactive control enabled navigation toward long-term objective while responding to nearby obstacles.
  • Dynamic Navigation & Real-Time Replanning: Evaluated navigation system under indoor scenarios with static environmental structures and changing obstacle configurations. Rather than assuming completely known and stationary world, architecture allowed local perception information to modify navigation behavior as robot moved. When trajectory became unsuitable, navigation pipeline could update local motion strategy or calculate alternative route, demonstrating importance of closed-loop perception and replanning.
  • Custom PCB Development & Hardware Integration: Designed and fabricated custom PCB specifically for this project, providing sensor interface board and power distribution for integrated LiDAR, camera, and IMU systems. Self-designed development board enabled optimized sensor integration, reduced wiring complexity, and provided dedicated power conditioning. PCB served as interface between TurtleBot 4 main platform and external sensor suite, demonstrating practical experience in electronic design, PCB layout, manufacturing, and hardware-software integration.
  • RViz Visualization & Debugging: Extensively used RViz to visualize robot model, sensor measurements, coordinate transforms, generated maps, localization estimates, planned trajectories, and navigation targets. Visualization critical for debugging distributed robotic system because failures could originate from sensor configuration, incorrect transforms, localization errors, planner parameters, or control behavior. Systematic visualization of intermediate outputs enabled individual subsystems to be validated before evaluating complete navigation pipeline.
  • Physical and Simulated Integration: Included navigation work with mobile robotic platforms such as AGV/TurtleBot-type systems, connecting algorithmic development to physical robot behavior. Considered practical limitations absent from purely theoretical planning, including sensor noise, wheel slip, imperfect odometry, restricted computational resources, communication timing, actuator dynamics, and differences between modeled and real environments. Emphasized not only successful path generation but reliable integration between software and physical robotic hardware.
  • Engineering Integration Outcomes: Provided practical experience across complete autonomous-navigation stack, including ROS 2, mobile robotics, LiDAR perception, IMU and odometry processing, SLAM, localization, sensor integration, TF coordinate transformations, occupancy maps, global and local costmaps, Dijkstra, RRT*, DWA, trajectory generation, obstacle avoidance, RViz visualization, PCB design, debugging, and physical robot validation. Strengthened experience in modular robotic software architecture and systems integration where perception, state estimation, planning, and control operate together reliably for autonomous navigation in real environments.

Development Process & Engineering Workflow

1

System Architecture & ROS Design

Designed modular ROS 2 architecture defining sensor integration strategy for TurtleBot 4. Established coordinate transformation hierarchy (map → odom → base_link → sensor frames). Defined standard topics, messages, and communication protocols between perception, planning, and control subsystems.

2

Custom PCB Design & Sensor Integration

Designed and fabricated custom PCB specifically for this project serving as sensor interface board and power distribution. Integrated LiDAR, RGB camera, IMU, and odometry onto development board. Optimized sensor layout, wiring, and power conditioning. Conducted sensor calibration and frame alignment to ROS TF system.

3

SLAM, Mapping & Localization Implementation

Implemented SLAM algorithms for simultaneous environment mapping and pose estimation. Developed occupancy grid representations. Tested localization methods for pose tracking in known and unknown environments. Evaluated mapping accuracy, odometry drift, and sensor uncertainty impacts.

4

Path Planning & Algorithm Evaluation

Implemented global planning algorithms: Dijkstra (deterministic shortest-path) and RRT* (sampling-based, progressive improvement). Developed DWA-based local navigation for reactive obstacle avoidance. Evaluated trade-offs between optimality, computation time, and path geometry. Tested algorithms in simulated and real environments.

5

Real-World Testing & Dynamic Navigation

Conducted extensive field testing in dynamic indoor and industrial environments. Evaluated navigation under static obstacles and changing configurations. Implemented dynamic replanning when trajectories became unsuitable. Used RViz visualization for real-time debugging of sensor, localization, and planning outputs. Refined system parameters based on physical robot performance and real-world validation.
