Project Overview

This project demonstrates comprehensive embedded system integration, combining hardware selection, firmware architecture, inter-task communication, sensor integration, actuator control, communications protocols, telemetry validation, and end-to-end system testing. The work emphasizes practical system-level engineering across multiple domains: embedded real-time systems, hardware-software interfaces, wireless communications, network debugging, and fault diagnostics.

1. System Architecture & FreeRTOS Real-Time Design

The embedded firmware was architected using FreeRTOS, separating system responsibilities into independent real-time tasks:

  • Sensor Acquisition Task: Periodic polling of SHT31 (temperature/humidity) and BH1750 (light intensity) sensors over I²C bus
  • Actuator Control Task: PWM-driven heater and digital fan control with safe initialization and state management
  • Control Logic Task: Hysteresis-based decision making for actuator automation based on sensor input
  • MQTT Communication Task: Asynchronous message publishing and command subscription for remote supervision
  • User Interface Task: Local button inputs and display output for manual overrides

Inter-task communication was implemented through queue-based snapshot architectures to avoid race conditions, reduce coupling, maintain deterministic behavior, and improve testability and system robustness.

2. Hardware-Firmware Integration & Sensor Interface

Performed complete hardware-software integration of the ESP32-S3 microcontroller with environmental sensing and actuation:

  • I²C Sensor Integration: SHT31 temperature/humidity and BH1750 light sensors interfaced over I²C protocol with bus scanning and recovery routines
  • Sensor Health Monitoring: Invalid reading detection, sensor timeout handling, and automatic re-initialization
  • Actuator Control Interfaces: PWM-controlled heater and digital GPIO fan control through MOSFET power stages for safe switching
  • Safe Startup Sequence: Actuators initialized to safe states, sensors verified before control loop activation
  • GPIO & PWM Configuration: Hardware abstraction layer isolating firmware from pin definitions and timing requirements

3. Bidirectional MQTT Telemetry & Remote Supervision

Implemented a complete bidirectional telemetry and command architecture using MQTT, connecting the embedded controller through a 250 m Wi-Fi link to a Raspberry Pi supervision system:

  • MQTT Broker (Mosquitto): Central message hub running on Raspberry Pi for sensor data, actuator commands, and configuration updates
  • Node-RED Automation: Flow-based logic for data routing, transformation, and trigger-based actions
  • InfluxDB Time-Series Database: High-performance storage of sensor readings and actuator states for historical analysis
  • Grafana Dashboard: Real-time visualization of sensor data, actuator states, system metrics, and historical trends
  • Manual Overrides: Remote command interface to bypass local control logic and manually actuate devices

4. Telemetry Health Monitoring & Fault Tolerance

Designed comprehensive telemetry health monitoring using multiple system metrics:

  • RSSI & Signal Strength: Wi-Fi link quality monitoring for 250 m wireless connection
  • Memory Management: Free heap memory tracking to detect memory leaks and resource exhaustion
  • Communication Latency: End-to-end latency measurement from sensor reading to dashboard update
  • Device Connection State: Automatic detection and reporting of MQTT connection status
  • Uptime & Reliability: System uptime tracking and automatic restart mechanisms
  • QoS & Message Reliability: MQTT QoS levels, retained messages, Last Will and Testament for robust communication
  • Automatic Reconnection: Wi-Fi and MQTT reconnection logic with exponential backoff for network resilience

5. Hardware-Firmware-Network Validation

Performed system-level and communication validation of the complete hardware-firmware-network pipeline:

  • 250 m Wireless Link Testing: Validated signal quality, message latency, packet reliability, and bidirectional communication stability
  • End-to-End Latency: Achieved stable connectivity and latency below one second under documented test conditions
  • Sensor Accuracy Validation: Cross-validation of sensor readings against reference instruments
  • Actuator Response Testing: Verified PWM control fidelity and actuator response time
  • Stress Testing: Continuous operation, message flooding, Wi-Fi interference, and network disconnection scenarios

6. Integration Debugging & Root-Cause Analysis

A major focus was integration debugging and root-cause analysis. Independently developed hardware, sensor, RTOS, control, and MQTT modules had to be merged into one deterministic system:

  • Shared Data Model Debugging: Resolving data consistency across multiple FreeRTOS tasks with queue-based architectures
  • Task Synchronization: Debugging race conditions, deadlocks, and priority inversion in multi-task execution
  • Queue Structures & Flow: Validating message routing, queue overflow handling, and circular buffer behavior
  • I²C Communication Issues: Bus scanning, clock stretching, device addressing, and error recovery
  • Sensor Failure Scenarios: Detecting stuck sensors, invalid readings, and implementing fallback behavior
  • MQTT Payload & Topic Analysis: Debugging message formatting, topic hierarchy, subscription issues, and retained message conflicts
  • Local vs. Remote Control Conflicts: Resolving inconsistencies between local manual overrides and remote automation commands
  • Iterative Integration Testing: Systematic testing of component interactions, boundary conditions, and edge cases
